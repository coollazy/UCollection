## 過程中的觀察 / 沒有預期到的狀況

- 本次沒有踩到任何套件相容性問題（`bs58check` 4.0.0 的 ESM `exports` 寫法，這次直接用 `.default` 取值就正確，跟驗證結論-01 記錄的坑一致，這次是已知問題，提前避開）。
- 交叉驗證的疊加效果：這次的 2 條路線 + 驗證項目 1 原本的 2 條路線，等於用**四套完全獨立的實作**（不同語言/函式庫/橢圓曲線庫組合）都算出同一組地址，對「HD 地址衍生數學正確」這件事的信心程度遠高於單一項目的驗證範圍。
- 本次驗證**只涵蓋衍生與簽名的數學正確性**，不包含：前端 JavaScript 實際執行環境（瀏覽器 vs Node.js）是否有行為差異、真實助記詞輸入 UI 的防護措施是否有效、簽名後的交易是否能被 Tron 節點正確廣播與執行（本次的簽名驗證是本地簽章/驗章，未實際廣播上鏈交易）。若要更完整驗證，可以額外做一次「用衍生出的私鑰在測試網簽一筆真實交易並廣播」，但這需要另外幫該衍生地址領測試幣，本次評估為非必要（上鏈廣播機制已在驗證項目 2 驗證過，殘餘風險低）。
