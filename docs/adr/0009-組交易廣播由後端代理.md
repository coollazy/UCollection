# ADR-0009：組交易與廣播統一由後端 `/tron-proxy` 代理

- Status: Accepted
- Date: 2026-09-01

## 背景

手動歸集、TRX手續費頁面需要在瀏覽器端衍生私鑰並簽名交易（伺服器全程不接觸私鑰的既有原則），但「組交易」（取得 unsigned raw data）與「廣播」（送出簽名後的交易）這兩個動作需要呼叫 TronGrid。若瀏覽器直接呼叫 TronGrid，CSP 的 `connect-src` 就必須放行外部網域，無法套用最嚴格的 `connect-src 'self'`。

## 決策

**組交易與廣播兩個對外呼叫 TronGrid 的動作，一律由後端經 `/tron-proxy` 代理執行**。瀏覽器只跟自家後端（同源）溝通，只負責衍生 xpub/私鑰與交易簽名，不直接連線 TronGrid 網域。

流程：前端呼叫 `/tron-proxy/.../prepare` → 後端呼叫 TronGrid 取得 unsigned `raw_data_hex`/`txID` → 前端本地重算 txID 核對 → 簽名 → 反推地址自我核對 → 前端把簽名結果 POST 給 `/tron-proxy/.../broadcast` → 後端呼叫 TronGrid `broadcasttransaction`。

## 理由

- 讓 CSP `connect-src 'self'` 可以直接套用，不必為了遷就直連需求而放寬——[驗證結論-08](../驗證結論-08-嚴格CSP下組交易簽名廣播.md) 已完整驗證這個架構下功能結果與未受限版本一致、無 CSP violation、無任何瀏覽器直連外部網域的請求。
- 「本地重算 txID 核對」與「簽名後自我核對」兩道防線確保即使後端回傳的 unsigned data 或後端本身被竄改，瀏覽器仍有機會攔截不一致的交易，不是把信任完全交給後端。

## 後果

- 適用範圍：手動歸集 USDT 轉出（`/tron-proxy/consolidation/...`）、TRX 手續費批次轉帳（`/tron-proxy/fee-topup/...`）。**不適用**於代收主錢包設定頁（僅本地 BIP32 運算取得 xpub，不查詢 TronGrid，不需要走 `/tron-proxy`）。
- `/tron-proxy/...` 路由額外要求已登入後台 session **且** 15分鐘內完成過 TOTP 新鮮驗證（見 [ADR-0011](0011-兩階段登入與step-up驗證.md)）。
