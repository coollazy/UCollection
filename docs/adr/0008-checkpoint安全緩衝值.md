# ADR-0008：checkpoint 安全緩衝 N = 20 個區塊

- Status: Accepted
- Date: 2026-09-02

## 背景

事件掃描背景任務（任務2）的 checkpoint 推進時需要保留安全緩衝（落後目前查到的最新區塊 N 個區塊），避免 TronGrid 索引延遲導致 checkpoint 推得太前面、之後才索引完成的事件被跳過漏記。N 值大小需要一個實測依據。

## 決策

**N = 20 個區塊（約60秒，@3秒/塊）**。

## 理由

- 原始草案誤用「約60秒」換算基準，但驗證項目2實測有兩個不同延遲：`only_confirmed=false` 約23.4秒、`only_confirmed=true`（solidified）約63.1秒。任務2 checkpoint 推進用的正是 `only_confirmed=false` 查詢，該用23.4秒這個數字，原文件誤套用了任務3（確認延遲）的數字。
- 23.4秒實測值（Shasta測試網單次觀察，非官方保證上限）套約2.5倍安全係數後取整數，得 N = 20 個區塊。
- 於 10/20/30 三個選項中選定20：N 值大小對系統幾乎無代價——只影響 EXPIRED/STALLED 守門判定延後的秒數（相對訂單有效期通常是分鐘級可忽略），不影響金額判斷正確性（`(tx_hash, log_index)` 唯一鍵已防重複），故沒有下修的理由。

## 附帶決策：防禦性降級告警機制

依 [驗證結論-09](../驗證結論-09-TronGrid事件掃描保留期限與斷點續掃.md) 建議：「未證明永久保留，只是沒測到截斷」，補齊掃描連續多個歷史區間都回傳空陣列、且理論上該有資料時，觸發告警/人工複查，不直接信任空陣列＝沒事件。這是對「TronGrid未公開保證未來行為」的防禦性設計，非本次驗證發現實際問題。
