# ADR-0012：TRX 手續費 A1/A2：不動用 index 0，改採商戶自訂地址

- Status: Accepted
- Date: 2026-09-02

## 背景

USDT 歸集是 `TriggerSmartContract`，執行需消耗能量，子地址預設無 TRX。需求書5.9拍板「A. 支付TRX」兩個來源選項：A1（代收主錢包簽名）、A2（任意錢包簽名）。草案初版把 A1 解讀為「動用代收主錢包底下的 index 0 地址」——因為 xpub 本身無「餘額」概念，不能直接收 TRX，必須先指定一個具體地址才有私鑰可簽名。

## 決策

**A1 與 A2 一律採完全相同的「商戶自行指定地址」機制，不動用 index 0**。商戶指定一個地址（可以是代收主錢包 HD 樹以外的任意地址，也可以是商戶自己另外持有的地址），輸入其助記詞或直接輸入私鑰，由該地址簽名批次轉出 TRX。A1 與 A2 在技術上完全一致，差異僅剩 `fee_source` 稽核欄位這個商戶自選的分類標記（A1＝商戶自認與代收主錢包相關的資金來源；A2＝商戶自認完全獨立的錢包）。

## 理由

- 需求書5.1明定 **index 0 保留、系統不賦予任何用途**（不分配訂單、不作系統內部用途、後台也不特別顯示）——若把它固定挪用為A1的TRX來源，等於系統賦予其具體用途，與需求書5.1字面直接衝突。
- xpub 本身無法直接持有/收取 TRX，任何「代收主錢包內的TRX」的說法本質上都要先落到一個具體地址，而不論是 index 0 還是任何其他 HD 樹內的地址，都需要商戶輸入對應的助記詞才能簽名——既然如此，直接讓商戶指定任意地址（不限定 HD 樹內），技術複雜度沒有增加，卻避免了 index 0 的語意衝突。

## 否決的替代方案

- **固定用 index 0 作為 A1 的 TRX 來源**：直接違反需求書5.1「index 0 系統不賦予任何用途」的字面規定，且商戶需要知道其餘額才能操作，牽動是否要在後台顯示這個原本「不特別顯示」的地址，會連動打開更多需要重新定義的問題。
