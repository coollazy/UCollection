# ADR-0004：不內建反向代理/TLS 終止

- Status: Accepted
- Date: 2026-09-01

## 背景

系統對外提供 API、後台、前台收銀頁三類端點，需要決定 HTTPS/TLS 終止與 rate limiting 由系統本身處理，還是交給部署環境。

## 決策

**系統本身不內建反向代理、不做 TLS 終止**，只監聽一般 HTTP port。假設商戶自行於前方架設 nginx/Cloudflare 等做 TLS 終止與 rate limiting。

## 理由

- 商戶自架情境下，多數商戶原本就會有自己的反代/CDN 層（或至少知道怎麼架一個），系統重複實作這塊只是增加維護面。
- 之後要加不難：docker-compose 多掛一個 container 擋在前面即可，不需改動現有程式碼。
- Rate limiting（前台收銀頁、對外API）統一交給這層處理，應用層不重複設計，避免兩層限流互相打架。

## 後果

- `admin_sessions` Cookie 的 `Secure` 屬性由環境變數 `COOKIE_SECURE`（預設 `true`）控制——正式部署預期前方有 HTTPS 反代；若商戶在無 TLS 的測試環境直接連線 `app` container，需自行關閉此旗標才能完成登入，此點須寫入部署文件。
- CSRF 防護的 `PUBLIC_ORIGIN` 環境變數需要商戶依自己對外網域正確填寫，App 啟動時若未設定即 fail-fast 拒絕啟動。
