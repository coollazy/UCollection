# ADR-0003：前端技術選型：html/template + htmx，零 Node.js 建置鏈

- Status: Accepted
- Date: 2026-09-01

## 背景

系統需要前台收銀頁（付款狀態輪詢更新）與後台管理介面，且部分頁面（代收主錢包設定、手動歸集簽名頁）需要在瀏覽器本地執行助記詞衍生與簽名這類高敏感邏輯。

## 決策

**Go `html/template` + htmx**，零 Node.js 建置鏈；僅高風險頁面單獨用 `esbuild` 離線打包對應函式庫。

## 理由

- 零 Node.js 建置鏈大幅降低部署複雜度與供應鏈攻擊面（商戶自架情境下，越少建置工具鏈依賴越好）。
- htmx 用 `hx-get` + `hx-trigger="every Ns"` 就能滿足前台收銀頁狀態輪詢刷新的需求，不需要 WebSocket/SSE 這類需要額外基礎設施的方案。
- 少量 inline vanilla JS（例如倒數計時的本地遞減顯示）不違反此原則——該原則限制的是**建置工具鏈**，不是禁止任何 JavaScript。
- 高風險頁面（助記詞/私鑰輸入）例外：這些頁面需要 `bip39`/`hdkey`/`@noble/curves` 等函式庫，且必須套用嚴格 CSP、離線打包、不從外部來源載入，`esbuild` 打包成單一靜態檔案是唯一符合這個安全要求又不必手刻密碼學函式庫的選項（見 [驗證結論-05](../驗證結論-05-離線打包與嚴格CSP相容性.md)）。

## 否決的替代方案

- **React/Vue + 完整前端建置鏈**：對這個規模的系統是不必要的複雜度，且與「零 Node.js 建置鏈」的部署簡化目標直接衝突。
- **WebSocket/SSE**：htmx 輪詢已足夠應付前台收銀頁的更新頻率需求（約5秒一次），不需要額外的持久連線基礎設施。
