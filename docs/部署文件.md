# UCollection 部署文件

本文件說明如何在自己的伺服器上部署 UCollection。你會拿到一個系統的 image 檔案（不是原始碼），依照下面步驟操作即可完成安裝、啟動，並完成後台管理員帳號的首次登入設定。

## 一、前置需求

- 一台已安裝 **Docker Engine** 與 **Docker Compose V2**（`docker compose` 指令，不是舊版獨立的 `docker-compose`）的伺服器/虛擬機。
- 這台機器需要能連上網路，用來下載資料庫用的官方 PostgreSQL image（`postgres:16-alpine`）。系統本身的 image 則是用 `docker load` 從檔案匯入，不需要額外網路存取。
- 已從提供方取得：
  - 系統 image 檔案（例如 `ucollection.tar.gz`），以及對應的 image 名稱:tag（例如 `ucollection:latest`）。
  - 自己要監控入帳的 USDT-TRC20 合約地址（正式環境為主網合約；若是先跑測試網，會是 Shasta 測試網合約）。
  - 對外服務會用的網址（例如 `https://pay.merchant.com`）。這個系統不內建反向代理/TLS，正式環境上線前務必先看第八節。

## 二、取得系統 image

在伺服器上，把系統 image 檔案放到工作目錄後匯入 Docker：

```bash
docker load -i ucollection.tar.gz
```

匯入完成後確認名稱與 tag 是否跟提供方告知的一致：

```bash
docker images | grep ucollection
```

## 三、準備部署檔案

建立一個空目錄作為部署目錄，在裡面建立 `docker-compose.yml`，內容如下：

```yaml
services:
  app:
    image: ${APP_IMAGE:-ucollection:latest}
    ports:
      - "${LISTEN_PORT:-8080}:8080"
    environment:
      LISTEN_ADDR: ":8080"
      DATABASE_URL: postgres://${POSTGRES_USER:-ucollection}:${POSTGRES_PASSWORD:?Set POSTGRES_PASSWORD in .env}@db:5432/${POSTGRES_DB:-ucollection}?sslmode=disable
      ENVIRONMENT: ${ENVIRONMENT:-production}
      NETWORK: ${NETWORK:-}
      USDT_CONTRACT_ADDRESS: ${USDT_CONTRACT_ADDRESS:-}
      PUBLIC_ORIGIN: ${PUBLIC_ORIGIN:?Set PUBLIC_ORIGIN in .env}
      TRONGRID_BASE_URL: ${TRONGRID_BASE_URL:-}
      TRONGRID_API_KEY: ${TRONGRID_API_KEY:-}
      ADMIN_USERNAME: ${ADMIN_USERNAME:-}
      ADMIN_PASSWORD: ${ADMIN_PASSWORD:-}
      COOKIE_SECURE: ${COOKIE_SECURE:-true}
    depends_on:
      db:
        condition: service_healthy
    restart: unless-stopped

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: ${POSTGRES_USER:-ucollection}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:?Set POSTGRES_PASSWORD in .env}
      POSTGRES_DB: ${POSTGRES_DB:-ucollection}
    volumes:
      - db-data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER:-ucollection}"]
      interval: 5s
      timeout: 5s
      retries: 10
    restart: unless-stopped

volumes:
  db-data:
```

再建立 `.env`（跟 `docker-compose.yml`放在同一目錄），內容見下一節。

## 四、設定 .env

把下面內容存成 `.env`，再依自己的情況修改：

```bash
# ==== image ====
# 對應第二節 docker load 匯入後、docker images 看到的實際名稱:tag。
APP_IMAGE=ucollection:latest

# ==== 網路 ====
# 對外服務用的 host port，預設 8080；只有這台機器 8080 已被佔用才需要改。
LISTEN_PORT=8080
ENVIRONMENT=production

# ==== 資料庫 ====
POSTGRES_USER=ucollection
POSTGRES_PASSWORD=change-me
POSTGRES_DB=ucollection

# ==== 對外網域 ====
# 商戶對外服務的網址，例如 https://pay.merchant.com。
# 系統開機時若沒設定這個值會直接啟動失敗（fail-fast），不會用預設值頂著跑。
PUBLIC_ORIGIN=https://pay.merchant.example

# ==== Tron 鏈上設定 ====
# 要連哪個 Tron 網路。不設定＝主網（正式環境維持不設定即可）。
# 測試時設成 shasta，系統會自動改用 Shasta 測試網的合約地址與節點端點，
# 不需要自己填合約地址。
# NETWORK=shasta
#
# 進階：若要接 Nile 測試網、自架節點、或 TronGrid 相容代理，才需要在這裡
# 手動指定合約地址/端點（會蓋過 NETWORK 的預設值）；一般部署不需要動這兩行。
# USDT_CONTRACT_ADDRESS=
# TRONGRID_BASE_URL=
# 選填。不設定的話會以較低速率限制的匿名額度呼叫 TronGrid。
# TRONGRID_API_KEY=

# ==== 後台管理員帳號 ====
# 只有資料庫是空的（第一次啟動）時才會拿這兩個值建立管理員帳號。
# 之後即使改這裡的值也不會覆蓋已存在的帳號——要改密碼請用後台「修改密碼」功能（見第七節）。
# 密碼至少需 12 個字元，否則系統會直接啟動失敗。
ADMIN_USERNAME=admin
ADMIN_PASSWORD=change-me-12-chars-min

# ==== Cookie 安全性 ====
# 正式環境務必維持 true（見第八節）。
# 只有在完全沒有 HTTPS、純本機/內部測試的情境才設為 false。
# COOKIE_SECURE=false
```

## 五、啟動系統

在部署目錄下執行：

```bash
docker compose up -d
docker compose ps
```

確認兩個容器都是 `running`（`db` 需為 `healthy`）。接著檢查系統本身：

```bash
curl -i http://localhost:8080/healthz
```

回應 `200 ok` 代表系統已啟動、且能連上資料庫。若沒有，先看 log：

```bash
docker compose logs app
docker compose logs db
```

`app` 的 log 應該會看到一行 `listening on :8080`，且沒有 fatal 錯誤退出。

## 六、開啟後台、首次登入與綁定兩步驟驗證

1. 用瀏覽器開啟 `<PUBLIC_ORIGIN>/admin/login`（例如 `https://pay.merchant.com/admin/login`）。
2. 輸入 `.env` 裡設定的 `ADMIN_USERNAME`/`ADMIN_PASSWORD` 登入。
3. 系統偵測到這是第一次登入，會自動導向兩步驟驗證（TOTP）綁定頁面，畫面上會有 QR code 與一組手動輸入用的金鑰。用手機上的驗證器 App（Google Authenticator、Authy 等任何支援 TOTP 的皆可）掃描 QR code，或手動輸入該金鑰新增一筆。
4. 輸入驗證器 App 當下顯示的 6 位數驗證碼完成綁定。
5. 完成後即可進入後台首頁。**之後每次登入都需要密碼＋驗證碼兩者**；若手機遺失導致驗證器遺失，需要有資料庫存取權限的人直接到 `admin_account` 資料表清除 `totp_secret` 欄位才能重新綁定，系統本身不提供應用層救援機制。

## 七、（建議）修改初始密碼

`.env` 裡的 `ADMIN_PASSWORD` 只在資料庫第一次建立管理員帳號時使用過一次，往後修改 `.env` 都不會再生效。建議登入後台後，到「設定 → 修改密碼」（`/admin/password`）換成自己記得住、且只有自己知道的密碼。

## 八、正式環境務必架設 HTTPS 反向代理

這個系統本身**不內建反向代理、不做 TLS 終止**——`docker-compose.yml` 只把 8080 對外開放 HTTP。正式環境上線前，必須自己在前面架一層 HTTPS 反向代理（nginx、Caddy、雲端負載平衡器等皆可，這份文件不限定工具），把外部的 HTTPS 流量轉發到這台機器的 8080 port。

架好反向代理後，確認 `.env` 這兩個值：

- `PUBLIC_ORIGIN` 設定為商戶對外實際的 `https://` 網址（不是這台機器內部的 http 位址）。
- `COOKIE_SECURE` 維持預設值 `true`。

如果還沒架好 HTTPS、暫時只是內部測試，才把 `COOKIE_SECURE` 設為 `false`——否則瀏覽器會擋掉登入後的 session cookie，導致登入後馬上又被導回登入頁。但正式對外服務前，這個值務必改回 `true` 並確保前面真的有 HTTPS。

## 九、更新版本

收到新版 image 後：

```bash
docker load -i ucollection-新版本.tar.gz
docker images | grep ucollection   # 確認新 tag
```

把 `.env` 裡的 `APP_IMAGE` 改成新的 tag（如果新版沿用同一個 tag 例如都叫 `latest`，這步可省略），再重啟 `app`（`db` 不受影響，既有資料不會被清除）：

```bash
docker compose up -d app
```

系統開機時會自動套用新版所需的資料庫結構更新（migration），不需要手動操作資料庫。

## 十、常見問題排查

- **`docker compose ps` 顯示 `app` 是 `Exited`**：看 `docker compose logs app`。常見原因是 `.env` 少填 `DATABASE_URL` 相關變數（`POSTGRES_PASSWORD`）或 `PUBLIC_ORIGIN`、`ADMIN_PASSWORD` 少於 12 個字元、或 `NETWORK` 填了 `mainnet`/`shasta` 以外的值。
- **`/healthz` 一直連不上或回 503**：先看 `docker compose logs db`、確認 `db` 容器是 `healthy`；再確認 `docker-compose.yml` 裡 `DATABASE_URL` 用的密碼跟 `.env` 的 `POSTGRES_PASSWORD` 一致。
- **登入或後台操作被拒絕（403）**：檢查瀏覽器網址列的網址（含 `http`/`https`、網域）是否跟 `.env` 的 `PUBLIC_ORIGIN` 完全一致——只要有落差（例如一個有 `www.` 一個沒有），系統的來源檢查就會擋下請求。
- **登入後過一下又被導回登入頁**：通常是還沒架 HTTPS 反向代理卻讓 `COOKIE_SECURE` 維持 `true`（見第八節），瀏覽器不接受在純 HTTP 連線上設定 Secure cookie，session 因此保不住。
